visor: a viewer for HTML and Markdown vaults, for people and agents.

A vault is a folder. visor shows its pages (.html, .md and
Excalidraw drawings) in a tree and renders the one you pick. If a
file changes on disk, the view updates by itself.

USE
  visor                      Opens the app.
  visor open <path|URL> [--tab | --beside] [--loose]
                             Opens a folder as a vault, shows a file or
                             loads a web page (http or https). Starts the
                             app if it is closed. Waits for the page to
                             load and returns the same as status, plus
                             "problems": the errors and warnings it
                             produced. If it does not load in 10 s, it
                             adds "warning".
                             With no options it replaces the active tab;
                             --tab opens a new tab; --beside opens it on
                             the other side (splits the window if needed).
                             An .html that is not in any vault opens as a
                             loose file. A .md note or a drawing outside
                             every vault opens its folder as a vault,
                             unless that folder is your home folder (~) or
                             the root (/): there it is an error.
                             --loose opens a .md outside every vault as a
                             loose file: its folder is not listed or added
                             to visor, and it cannot be annotated, but
                             Ctrl+E edits it and saves to the file. Its
                             [[links]] and images are found by name only
                             in its folder and subfolders (not hidden ones).
                             A .md inside a vault opens in that vault.
  visor close [<path>]       Closes the active tab of the focused side.
                             With a path, closes every tab that shows that
                             file, on either side. Returns "closed" (how
                             many it closed) and the same as status. If no
                             tab shows it, it is an error.
  visor status               The vault and file the person is viewing:
                             "file" (null on a web page; the absolute path
                             if it is a loose file), "url" (on a web page),
                             "path" (absolute path), "loaded" (finished
                             loading), "errors" (errors in its console),
                             "sides" (tabs of each side: "list" from left
                             to right, and "active"), "focused" (the side
                             with focus), "window" (the window it describes),
                             "windows" (every open window: its "window",
                             whether it is "focused" and its "vault") and
                             "last_event_id" (for events --after).
  visor reload               Reloads the current page. Returns the same
                             as open.
  visor console [--errors] [--clear]
                             Console of the current page: console.log,
                             JavaScript errors, resources that did not
                             load and rejected promises. Keeps up to 100
                             messages per second; if there are more, a
                             line says how many were skipped.
  visor screenshot <file.png>
                             PNG capture of what the person sees in the
                             active tab, drawn by visor's engine (WebKit).
                             Only vault or loose pages. The path must end
                             in .png and is replaced if it exists. Returns
                             "path" and "bytes".
  visor eval <js>            Runs JavaScript in the active tab and returns
                             "value" (JSON) and "type" (the JavaScript
                             type). Only vault or loose pages, never web
                             pages. Returns the value of the last
                             statement; does not wait for promises.
                             Example: visor eval "document.title".
  visor events [--after ID] [--wait SEC] [--limit N]
                             Data that pages sent with visor.send() and
                             messages the person writes in their
                             annotations. With no options, the last 20
                             (1000 are kept, also after a restart). With
                             --wait, waits up to SEC seconds (maximum 600)
                             for a new one to arrive. Each event has
                             "window": the number of the window it came from.
  visor notes [path|--all]   Annotations of the open page, of another
                             page or of the whole vault (a path and --all
                             cannot be combined). For the open page,
                             "anchored" says whether each one still finds
                             its text or element. In a PDF, a note whose
                             page is not shown yet is not reported as lost:
                             it waits until the page is drawn.
  visor notes reply <id> <text>
                             Replies to an annotation; the person sees it
                             at once in their note.
  visor update               Checks for a new version now (without waiting
                             for the daily check) and installs it if there
                             is one. Returns "message" with the result. It
                             does not restart visor: the new version is
                             used when it is opened again. A copy in
                             target/ is not replaced.
  visor mcp                  MCP server over stdio (see MCP).
  visor help                 This help.

Every command answers in JSON. "ok": false means an error, and the
command exits with code 1. <path> can be relative to the current folder
or to the open vault.

WINDOWS
  --window N (before or right after the command name, not after eval)
  sends the command to window N. Windows are numbered from 1. Without it,
  the command goes to the focused window.

MCP
  Register the server with: claude mcp add visor -- visor mcp
  Each tool is equivalent to a command. Arguments:

      open         target (path or URL), place ("here", "tab" or "beside")
      any tool     window (number, as in --window; without it, the focused window)
      close        target (absolute path; without it, the active tab)
      status, reload
      console      errors_only (= --errors), clear
      screenshot   path (absolute path ending in .png)
      eval         code (JavaScript)
      events       after, wait, limit
      notes        page (one path) or all, not both
      notes_reply  id, text
      update       checks for a new version and installs it; does not restart
      guide        returns this text

TABS AND SIDES
  The window can be split into two sides, each with its own tabs.
  open, reload, console and notes act on the active tab of the side
  with focus: what the person is looking at. close does the same, or
  closes the tabs of a file given by path. Only 3 pages stay loaded at
  the same time; the other tabs reload when you go back to them, and
  their console starts empty.

LOOSE FILES
  To show a quick sample you do not need a vault:
  `visor open /path/sample.html`.
  - Its folder does not become a vault and is not added to the list. With
    the app closed, it opens without the panel and without the last vault;
    with a vault open, it goes to a tab and the vault stays as it was.
  - Paths relative to its folder and subfolders work, but not those that
    leave it (../) or files and folders that start with a dot. It has its
    own origin: it cannot read the vault.
  - It reloads by itself if it or the files in its folder change (not the
    files in subfolders).
  - It has visor.send(), `visor console`, `visor reload`, `visor eval` and
    `visor screenshot`, but no annotations.
  - To open its folder as a vault: `visor open <folder>`.

MARKDOWN NOTES
  - .md files appear in the tree next to the .html files and are shown
    rendered with the theme. They support tables, footnotes, task lists,
    alerts (> [!NOTE]), formulas ($...$ and $$...$$, KaTeX), syntax-
    highlighted code and diagrams (```mermaid blocks, drawn with Pele).
  - YAML front matter is shown as a property table above the text. Top-
    level keys with text, lists ([a, b] or lines starting with "- ") and
    multi-line text (> or |) are read; anything nested is shown as text.
    If a line is not "key: value", the block is shown as it is.
  - A "lang" key (lang: en, lang: es-MX) sets the language of the note
    for spell checking, hyphenation and screen readers. Without it, the
    note takes the language of the interface.
  - Obsidian-style links: [[note]], [[folder/note]], [[note#Section]] and
    [[note|text]], looked up by name across the whole vault. With folders,
    the path from the vault root or its end is enough: [[phases/note]]
    finds course/phases/note.md. A link to a note that does not exist
    creates it when clicked; if it has folders ([[folder/note]]), it is
    created from the vault root, and any missing folders are created too.
    ![[photo.png]] shows an image looked up by name.
  - PDF files: [[report.pdf]] and [text](report.pdf) open the PDF in visor,
    looked up by name like a note, in visor's PDF viewer (see PDF FILES). ![[report.pdf]]
    does not embed it. A link to a PDF that does not exist is not created:
    it is shown as a dead link. The person can highlight and comment on the
    text of a PDF, but visor never changes the PDF file and cannot edit it.
    In the tree, a PDF opens like a page (Ctrl: new tab).
  - The person ticks tasks (- [ ] / - [x]) with a click and visor saves it
    to the .md. It reads the file again before changing it.
  - It warns the person before you edit a note that is open in the editor:
    they will see a warning and their editor does not change, and if they
    keep typing, their text replaces yours.

EXCALIDRAW DRAWINGS
  - visor shows and edits two formats: .excalidraw.md (the one from the
    Excalidraw plugin for Obsidian) and .excalidraw (JSON from
    excalidraw.com). They appear in the tree next to the other pages.
  - They open in read-only mode. Ctrl+E edits them. They save by
    themselves, 0.8 s after the last change, in the same format they had.
  - In an .excalidraw.md, "## Text Elements" and "## Element Links" are
    regenerated from the drawing. From "## Embedded Files" the line of each
    deleted image is removed (if none are left, the whole section); the
    image file stays in the vault. The rest of the file (front matter and
    other text) is kept as it is.
  - Images in "## Embedded Files" are looked up by name in the vault.
    Images by URL are shown only as images: no page reads their content,
    although `visor screenshot` captures them. When exporting to PNG or SVG
    they become gaps, and a warning says so. LaTeX formulas (`<id>: $$…$$`)
    are drawn with KaTeX, which only loads in drawings that have one.
  - An image pasted or inserted into an .excalidraw.md is saved next to the
    drawing as "<name> <date and time>.png" (or .jpg, .webp, .gif), with
    " 2", " 3"… if it already exists. Only PNG, JPEG, WebP and GIF, up to
    10 MB; not SVG. If it cannot be saved, the status bar says so and the
    drawing is not saved until you delete the image.
  - `visor screenshot` is useful to check the result.

PDF FILES
  - A .pdf of a vault opens in visor's viewer: the full viewer of PDF.js
    (the one in Firefox), in the person's language. Its toolbar has the
    sidebar (thumbnails, outline), Find (Ctrl+F), the page number, the
    zoom (Ctrl+plus, Ctrl+minus, Ctrl+0 change it while the PDF is in
    front), print and download. Its menu has rotate, presentation mode,
    scroll and spread modes and document properties.
  - The viewer's own drawing and highlighting tools are off: the person
    annotates with visor's annotations, which never change the file.
  - Scripts inside a PDF do not run. "Open with another application", in
    the viewer's menu, opens the file with the system's PDF program
    (visor is skipped if it is the default).
  - A PDF with a password is not opened: the viewer says it failed.
  - A PDF outside every vault opens as a loose file, in WebKit's own
    viewer, and cannot be annotated.

ANNOTATIONS
  The person highlights text, comments on it, or annotates an element or a
  point (a chart, an image, a canvas; not in PDFs). They are saved apart, in
  <vault>/.visor/anotaciones/<page path>.json, and do not change the page.
  Reply with `visor notes reply`; do not edit those files.
  - "target" says where: the quoted text ("quote.exact", with the context
    "prefix" and "suffix") or the element ("element": tag, id, CSS
    selector, text), and the point ("point": x and y from 0 to 1).
    In a PDF, "target.page" is the page number (from 1) and "quote.start"
    is the offset in that page's text; there are no elements or points,
    only highlighted text. The "page" field of each note is the PDF file.
  - "title" names element annotations (the name the person gave or a
    computed one, e.g. "Diagram in “Ondas”"); older ones may not have
    it. Add aria-label, alt or a caption (figcaption, caption) to charts,
    images and tables so the title says what they are.
  - Each annotation is a conversation: "comment" is what the person wrote,
    and "replies" are the following messages in order, with "author"
    ("persona" or "agente", the literal values) and "text".
  - "pending": true means the person is waiting for your reply (the last
    message is theirs). After your reply it becomes false.
  - A new or edited comment, or a reply from the person, reaches
    `visor events` as an event with "file" and "annotation" ("id",
    "action": "comment" or "reply", "text"), without "data". Events from
    visor.send() always carry "data".
  - If you change the page, annotations are re-anchored by themselves as
    long as the quoted text exists. If you remove it, they become orphans
    ("anchored": false) and the person sees them in their list. Keep the
    annotated text when you can.

WRITING PAGES FOR VISOR
  - Each page is a self-contained .html file. JavaScript, CSS and libraries
    from a CDN are allowed. Relative paths work (images, CSS, JS, JSON,
    video, audio and links to other pages).
  - They are served from 127.0.0.1 with a fixed origin, so localStorage and
    IndexedDB persist. All vaults share the origin: use keys with your own
    prefix, e.g. "fisica/ondas:progreso".
  - The errors in `visor console` use vault paths, such as
    historia/roma.html:2:69 (file, line, column).
  - A resource that does not load (CSS, image, script, fetch, and also an
    @import inside another CSS file) appears as an error, with the vault
    path and the HTTP code ("responded 404") or "network error". If it comes
    from another website, only its server is named, without path or detail:
    "Could not load a resource from cdn.jsdelivr.net (network error)".
  - Folders that start with "." and node_modules are not shown. Symbolic
    links to folders are followed only if they point inside the vault, and
    each real folder is listed once.
  - Links: http and https open inside visor; mailto opens the mail app;
    other schemes are ignored. target="_blank" opens a new tab; Ctrl+click
    or middle click, a tab that loads when shown.
  - External websites have no visor.send() and their console is not
    recorded: what they publish must not reach an agent. That is why
    `visor eval` and `visor screenshot` do not work on them either.
  - window.visor.send(data) sends any serializable data to `visor events`,
    which stores it with id, time, vault and file:

      visor.send({ type: "answer", question: 3, chosen: "b" });

    Each page can send at most 100 events per second, and each one up to
    16 KB serialized. Anything beyond that is discarded, and a line in
    `visor console` says how many events were skipped or that one was too
    large.
  - The "kit:review" event on window, fired by the review blocks of the
    study kit, is forwarded with visor.send(e.detail) and the same limits.

  - With Omarchy, each page receives the theme colors as CSS variables,
    updated when the theme changes:

      --visor-bg  --visor-fg  --visor-accent  --visor-muted
      --visor-selection  --visor-mode (light or dark)
      --visor-red  --visor-orange  --visor-yellow  --visor-green
      --visor-cyan  --visor-blue  --visor-magenta  --visor-brown
      --visor-font-mono

    Outside Omarchy they do not exist: use a fallback value.

      body { background: var(--visor-bg, #fff); color: var(--visor-fg, #222); }

  - If the theme changes while the page is open, the "visor:tema" event
    arrives with the mode, "dark" or "light", in e.detail.modo. The
    --visor-* variables already have the new values when it arrives. Use it
    to redraw a canvas, Three.js or a chart:

      addEventListener("visor:tema", (e) => {
        const css = getComputedStyle(document.documentElement);
        dibujar(css.getPropertyValue("--visor-bg").trim(), e.detail.modo);
      });

TYPICAL AGENT WORKFLOW
  1. Write or edit the HTML in the vault.
  2. `visor open <file>` to show it and see its errors; if there are any,
     fix them and `visor reload`.
  3. If the page asks the person for something, or to follow their
     annotations, wait with `visor events --wait 300`.
  4. With an "annotation" event: read the conversation with `visor notes`,
     reply with `visor notes reply <id> <text>`, and wait again.

UPDATES
  visor checks for a new version at startup, at most once a day, and
  installs it by itself for the next start. It can be turned off in Settings
  (Ctrl+,). A binary built with cargo is not touched.

SEARCH FROM THE BAR
  What is typed in the bar (Ctrl+L) that is not a URL, a vault path or a
  domain (such as "example.com") is searched with the search engine chosen
  in Settings (Ctrl+,): DuckDuckGo, the default, or Google. The search opens
  in the current tab.
  - Starting with "?" forces a search: "? ondas" searches for "ondas" even
    if it looks like a path or an address.
  - A mistyped path (with "/", such as "study/physics/waves", or with an
    extension, such as "waves.md") is an error and is not searched, so the
    name of a note is never sent to a search engine by mistake.

SHORTCUTS IN THE APP
  Ctrl+O  open folder        Ctrl+B  show or hide the panel
  Ctrl+R / F5  reload
  Ctrl+L  address bar: URL, domain, vault path, absolute path or search.
          Escape leaves the bar (in an empty tab, the tab stays blank).
  Ctrl+Shift+B  show or hide the bar (starts hidden; remembered;
          Ctrl+L shows it while you type)
  Ctrl+E  edit the open .md note or drawing, or go back to the view
  Ctrl+N  new note in the folder of the current one
  Ctrl+Shift+A  annotate an element or a point
  Ctrl+Shift+L  list of the page's annotations (both buttons, on the right
          of the tabs, only on vault pages)
  Ctrl+T  new tab, with the cursor in the bar (or "+")
  Ctrl+W  close it (or middle click)
  Ctrl+Tab / Ctrl+Shift+Tab  next / previous tab
  Ctrl+1 … Ctrl+8  tab number N of the focused side; Ctrl+9, the last one
  Ctrl+| (o Ctrl+\)  split the window or go back to one side
  Ctrl+Alt+←  Ctrl+Alt+→  left or right side
  Ctrl++  Ctrl+-  Ctrl+0  zoom in, out or reset (remembered); in a PDF,
                          the viewer's own zoom
  Ctrl+,  settings: theme, text size, updates and search engine
  Ctrl+F  search in the page: Enter next, Shift+Enter previous, Esc closes.
          In a PDF or a note's editor, their own search.
          In a page of the vault or a loose file, every match is marked and
          the current one is orange; the counter is exact there.
          The search stops at 1000 matches: past them it reads
          "1 de más de 1000".
  Ctrl+K  list of shortcuts. In an Excalidraw drawing, Ctrl+K is still
          Excalidraw's link.
  Alt+←  back    Alt+→  forward (also the mouse side buttons)
  Panel:
  - The divider can be dragged and is remembered. Ctrl+click opens in a
    new tab; Ctrl+Alt+click, on the other side.
  - Dragging a file onto the left or right half of the page splits the
    window and opens it on that side; with the window already split, it
    opens in a new tab on the side where it is dropped.
  - Right click or Del on a file or folder sends it to the trash with its
    annotations. Dragging it to another folder moves it; dropping it on
    the empty space moves it to the root. When moving, links in .md notes
    are updated, not those in HTML pages.
  - A file that visor does not open can be opened with another application,
    from the right click or from the notice that appears when you click it.
  - The folder button, next to the "+", creates folders; right click on a
    folder creates notes or folders inside it.
  Each vault remembers its tabs and its split.
